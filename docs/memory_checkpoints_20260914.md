# 内存依赖、矩阵乘检查点与回放验证

最终测试源码为 `ed332733db28dbf16de06f166b16766760148958`。本轮把错误定位从寄存器值依赖扩展到实际内存读写，补齐重叠视图的独立回放，并检查矩阵乘分解的内部步骤。**460 项选定 CPU 回归通过；同源码 A100-SXM4-40GB 完整回归为 835 passed、2 skipped，570.53 秒，退出 0。** [原始证据索引](../results/memory_checkpoints_20260914/README.md)

## 实际改进

| 功能 | 现在的行为 | 边界 |
|---|---|---|
| 内存读写来源 | 记录活动地址对应的相对字节区间，将读取连接到同一 program 最近一次实际写入 | 过滤记录、未知 handler、跨 program 顺序和重叠写入 lane 明确报告不确定性 |
| 共享存储回放 | 独立复制并恢复重叠视图、负/零步长、只读权限、不同 dtype 和同对象别名 | 只支持数值数据；检查保存缓冲区范围，未被输入覆盖的间隙填零；不模拟 GPU 并发 |
| 矩阵乘中间检查 | 对照原始输入检查左右取值、乘积及逐步累加前缀，定位错误索引、乘法和累加操作 | 要求每个有效 lane 按顺序完整执行 K；不能把任意重排、split-K 或 FMA 当作同一种标量契约 |
| 分析效率 | 按生产者建立 trace 索引，只回溯观测点之前的执行；纯值记录跳过内存历史构建 | 分析时间仍取决于记录和数值规模；没有普遍最优或所有场景加速的承诺 |
| 版本兼容 | 新失败包使用 schema 2 与 diagnostics_version 2，验证内存和投影字段；历史包按原诊断语义回放 | SSA 和输入能够重放；不会执行导出的任意 Python pass，也没有自动缩减程序或 shape |

记录中不保存进程内存地址。快照和 watch 不进入实际读写记录；掩码先排除无效地址，再转换活动坐标。矩阵乘检查点从原始输入独立计算预期值，不以候选中间值自证正确。标量 tensor.extract 只读取选定坐标。

## 验证范围

本轮新增 **77 项测试**：内存依赖35项、矩阵乘检查点24项、共享存储15项、索引及无内存快速路径3项。它们包含在 CPU 460 项和 A100 835 项中，不额外累加。上轮55项结果映射测试也继续运行。

- CPU 环境无 Torch/Triton，15项实际GPU测试被明确取消选择；严格 Sphinx 另用真实 CPU Torch 环境构建通过。
- 普通 wheel 在独立环境以 `--no-deps` 安装，67份包源码逐字验证；仍保留原Triton依赖元数据，并未发布独立CPU发行包。
- 每个包使用安装环境的 `python -I` 独立回放：4个已有定位接口的新故障包、20个矩阵乘内部故障包、1个共享内存故障包，以及9c5ffba和adf658e两代各4个历史包，全部通过。
- A100同源码15项Triton差分和独立CUDA dot四路对照通过；15项已经包含在完整835项内。独立CUDA dot仍是一个float32标量分解正确性案例，不代表完整CUDA后端覆盖或Tensor Core性能。
- 全库行覆盖率为 **86.43%（10069/11650行）**，不是解释器专项或分支覆盖率。两个skip分别要求至少双GPU进行AOT跨设备和Triton多上下文测试。

这些故障是有明确预期的人工注入，用于检验定位和回放能力，不冒充新发现的上游缺陷。Ruff、format及项目贡献风格检查均通过，所有测试保留原计算容差。

## 分析时间对照

对照源码为上一版 `3757a1d`，在同一CPU进程中分别预热后做7轮交错测量。以下均为中位数；每轮核对诊断内容一致。**只测诊断分析，不含trace生成、编译或GPU执行。** [全部原始样本](../results/memory_checkpoints_20260914/cpu/ed33273/analysis-benchmark/benchmark.json)

| 操作/映射数量 | 结果映射：原版 → 新版（ms） | 原版时间/新版时间 |
|---|---:|---:|
| 256 | 9.979 → 2.994 | 3.33× |
| 1024 | 137.782 → 13.172 | 10.46× |
| 4096 | 2070.220 → 61.171 | 33.84× |

早期观测点的回溯约为原版的3.06–3.81倍速度。末尾观测点没有统一收益：256和1024操作规模分别增加约0.037ms、0.142ms，4096规模从10.103ms降至9.923ms；这些结果均保留。不能把33.84×写成GPU算子加速比。

首版 `3312a79` 的CPU459/15和A100834/2都通过，但其纯值记录仍构建了不需要的内存历史。基准暴露末尾回溯开销后，`ed33273`增加快速路径和回归测试，再完成460/15及835/2验收。两版源码、性能样本和原始记录分别保存；两次整套耗时受缓存影响，不作算法加速比。
