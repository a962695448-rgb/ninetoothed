## 完整回归为什么未完成

本轮为 `NINETOOTHED_CACHE_DIR` 和 `TRITON_CACHE_DIR` 指定新目录，首次编译耗时显著增加。运行过程持续有 CPU 活动和缓存写入；算力窗口结束前，控制器向已核对身份的 pytest 子进程发送 SIGINT，使其有时间写出中间结果。最后停在卷积 `padding3` 用例，控制台记录 KeyboardInterrupt；此前已完成的断言没有失败。

原始状态为 `FAIL`、退出码2，不能改写为成功，也不能用84项部分通过代替705项完整回归。此次没有完整覆盖率产物，不报告覆盖率百分比。

JUnit 的 suite 统计为86个已完成条目，与控制台的84通过、2跳过一致；文件另有一个无 classname、名为 `testcase` 的中断附加元素。不能简单把所有无 failure 子节点的 XML 元素计为通过。

两个跳过项均要求至少两张 CUDA GPU：

- 多设备 AOT 测试：`tests/test_aot.py:52`。
- Triton 跨 CUDA context 测试：`tests/test_built_artifact_reload.py:74`。
